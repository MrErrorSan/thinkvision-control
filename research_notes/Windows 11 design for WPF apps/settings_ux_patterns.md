# Windows 11 UX patterns and control guidance for a small settings-style utility (monitor-control app)

Scope: Microsoft-documented guidance (as of October 2026) on page structure, control choice, states, dialogs, title bar, notification-area (tray) behaviour and shortcut editing, applied to a monitor-control app. Most current docs target WinUI 3; for a WPF app they define the target look and behaviour, not the API. Where a source is the legacy Windows 7 "UX guide" (win32/uxguide), that is flagged: Microsoft itself says those pages "have not been updated for newer versions of Windows. Much of the guidance still applies in principle."

## Page structure: NavigationView, page headers, settings cards (SettingsCard / SettingsExpander), spacing, group headers

### Takeaway
Use a single scrolling column of SettingsCards (header + description + icon on the left, control on the right), grouped under BodyStrong section headers. Cards are spaced 4 px apart, section headers have a 30 px top margin and 6 px bottom margin, and content has a max width of about 1000–1064 px. Add a NavigationView only if there are several pages: Left pane for 5–10 items, Top pane for 5 or fewer. Settings goes at the bottom of the pane.

### Cited Findings
- Settings page layout: "The app settings page should open full-screen and fill the whole window. Use a scrollable layout with a constrained max width (around 1000–1100 px) so content remains readable on wide displays. Group related settings under section headers using the **BodyStrong** text style." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- Microsoft now explicitly recommends the Community Toolkit settings controls: "Use the SettingsCard and SettingsExpander controls from the Windows Community Toolkit to build your settings page. These controls provide a consistent, accessible layout with a header, description, icon, and an action control aligned to the right side of the card." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- SettingsCard anatomy: "Each card has a **Header**, an optional **Description**, an optional **HeaderIcon**, and an action control (such as a `ToggleSwitch`, `ComboBox`, or `Button`) placed as the card's content. Setting the `IsClickEnabled` property to `true` makes the entire card clickable, which is useful for navigation-style entries." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- SettingsExpander: "Use a SettingsExpander when a setting has sub-options that should be revealed on demand. The expander shows a primary action control on the header row and additional `SettingsCard` items inside the `Items` collection... Avoid nesting expanders deeper than one level." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- "Combine less-used settings into a `SettingsExpander` so that common settings can each have their own `SettingsCard`. Put content or links that only contain information in an 'About' section." "Present content from top to bottom in a single column, scrollable if necessary." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- "Use descriptive, one-word labels for settings headers. For example, name the setting 'Accounts' instead of 'Account settings'." "Try to keep the total number of settings to a maximum of four or five." (This applies to an app's own settings page.) — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- About section: "We recommend placing an **About** section at the bottom of your settings page using a `SettingsExpander`. The collapsed header row should show your app name, icon, and version number." The expanded area can hold repo/website link, bug-filing link, dependencies as HyperlinkButtons, and legal links. — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- App theme setting: present in a ComboBox inside a SettingsCard with options "Light", "Dark", "Use system setting", and optionally a hyperlink "Windows color settings" to `ms-settings:colors`. — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- Exact spacing tokens in the Toolkit's reference settings page: `<x:Double x:Key="SettingsCardSpacing">4</x:Double>`. The section header style `SettingsSectionHeaderTextBlockStyle` is BasedOn `BodyStrongTextBlockStyle` with `Margin="1,30,0,6"`. The StackPanel inside a ScrollViewer has MaxWidth 1000. — [CommunityToolkit SettingsPageExample.xaml](https://raw.githubusercontent.com/CommunityToolkit/Windows/main/components/SettingsControls/samples/SettingsPageExample.xaml)
- WinUI 3 Gallery's own settings page: page header TextBlock `Style="{StaticResource TitleTextBlockStyle}"`, `MaxWidth="1064"`, `Margin="36,24,36,0"`. Content padding is `36,0,36,0`, with the same SettingsCardSpacing of 4 and the same section-header style (`1,30,0,6`). It uses ComboBox and ToggleSwitch in cards, SettingsExpanders for grouped sub-settings and About, and FontIcon glyphs as card icons. — [WinUI-Gallery SettingsPage.xaml](https://raw.githubusercontent.com/microsoft/WinUI-Gallery/main/WinUIGallery/Pages/SettingsPage.xaml)
- The SettingsCard sample uses `<StackPanel Spacing="4">`. HeaderIcon can be a FontIcon, SymbolIcon or BitmapIcon. Content wraps under the header below the `SettingsCardWrapThreshold` resource, and the icon hides below `SettingsCardWrapNoIconThreshold` (the sample overrides these to 800/600). Clickable cards show an ActionIcon (customisable via `ActionIcon`/`ActionIconToolTip`, hideable via `IsActionIconVisible="False"`). — [SettingsCard docs](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/windows/settingscontrols/settingscard)
- A card's Description can hold custom content such as a HyperlinkButton ("Learn more about Phone Link"), and a card can carry an accent button as its action ("Open Phone Link", `AccentButtonStyle`). — [SettingsCard docs](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/windows/settingscontrols/settingscard)
- NavigationView pane choice: Top when "You have 5 or fewer top-level navigation categories that are equally important". Left when "You have 5-10 equally important top-level navigation categories" or "You want navigation categories to be very prominent". — [NavigationView](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview)
- NavigationView Auto adaptive behaviour: "An expanded left pane on large window widths (1008px or greater). A left, icon-only, nav pane (`LeftCompact`) on medium window widths (641px to 1007px). Only a menu button (`LeftMinimal`) on small window widths (640px or less)." — [NavigationView](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview)
- NavigationView Header: "It has a fixed height of 52 px. Its purpose is to hold the page title of the selected navigation category." "We recommend 12px margins for your content area when NavigationView is in `Minimal` mode and 24px margins otherwise." — [NavigationView](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview)
- Settings entry point: "app settings should be the last item in the list of navigational choices and be pinned to the bottom" (`IsSettingsVisible`). FooterMenuItems appear before Settings. "Only Navigation items should be placed in FooterMenuItems". — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings); [NavigationView](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview)
- SelectorBar is for switching "between a small number of different sets or views of data". Use NavigationView "when you require consistent, top-level app navigation that adapts to different window sizes". Use RadioButtons "when an option is not selected by default, and context is unrelated to page navigation". — [SelectorBar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/selector-bar)
- PowerToys (closest Microsoft reference app) GeneralPage: a `SettingsPageControl` container with module image and primary/secondary links. SettingsGroups such as "Version & updates", "Startup and permissions", "Appearance & behavior", "Backup & restore", "Diagnostics & feedback". Inside the groups are SettingsCards/Expanders with toggles and combo boxes. — [PowerToys GeneralPage.xaml](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Views/GeneralPage.xaml)
- PowerToys utility pages put an enable toggle at the top of each utility page ("using the toggle at the top of the page to enable/disable"). This was found via a third-party summary, not a primary Microsoft source. — [mintlify PowerToys FAQ](https://mintlify.com/microsoft/powertoys/community/faq)

### Inferences
- With only a few areas (e.g. Display, Advanced, Hotkeys, App settings), a monitor app could use a single page with section headers ("Brightness & colour", "Input", "Advanced", "Hotkeys", "App") and no NavigationView. That matches the single-column guidance and avoids a nav pane for 3–4 items. If pages are used, Left NavigationView with Settings pinned at the bottom matches the Settings app and PowerToys. Top is acceptable for 5 or fewer pages.
- Card recipe for WPF: card spacing 4, section header BodyStrong with margin 1,30,0,6, content padding about 36 horizontal, max width about 1000–1064, page title in Title style.
- Factory reset and power off fit as SettingsCards with a standard (not accent) Button as the action, in an "Advanced" or "Device" group, each followed by a ContentDialog. Input source and colour mode fit as ComboBox cards. "Run in background" and "Start with Windows" fit as ToggleSwitch cards. An expander suits options that depend on a parent toggle (e.g. "Run in background" → "Start minimised").

### Gaps
- No Microsoft doc gives the exact pixel anatomy of a SettingsCard (min height, internal padding, icon size, header/description type ramp). It is defined in the Toolkit's control template, which I did not fetch. Read `SettingsCard.xaml` in CommunityToolkit/Windows for exact values.
- Breadcrumbs: no Settings-app-specific guidance found. Windows Settings uses a breadcrumb-style page title for sub-pages, but I found no Microsoft design doc that prescribes it for third-party apps (BreadcrumbBar control docs were not fetched).

## Control choice: ToggleSwitch vs CheckBox vs RadioButtons vs ComboBox vs Segmented/SelectorBar; Slider; buttons; hyperlink buttons

### Takeaway
On a settings page every change should apply immediately: ToggleSwitch for binary settings, RadioButtons for up to about 5 equally weighted options, and ComboBox for compact or longer lists (more than 8 options, or when a default is recommended). Slider is for relative continuous quantities like brightness and contrast, with immediate feedback and a visible value. Buttons are for immediate actions, and HyperlinkButtons are for navigation. Use accent colour sparingly.

### Cited Findings
- "Use a toggle switch for binary operations that take effect right after the user flips the toggle switch." "label it with one or two words, preferably nouns". — [Toggle switches](https://learn.microsoft.com/en-us/windows/apps/design/controls/toggles)
- ToggleSwitch vs CheckBox: "Use a toggle switch for binary settings when changes become effective immediately"; "Use check boxes for optional ('nice to have') items"; "Use a checkbox when the user has to perform extra steps for changes to be effective... if the user must click a 'submit' or 'next' button"; "Use check boxes when the user can select multiple items that are related to a single setting". — [Toggle switches](https://learn.microsoft.com/en-us/windows/apps/design/controls/toggles)
- "Use the default On and Off labels when you can... if the words 'On' and 'Off' don't describe the action tied to a toggle switch, you might need a different control." — [Toggle switches](https://learn.microsoft.com/en-us/windows/apps/design/controls/toggles)
- Settings-page control list: Toggle switches for on/off. "Radio buttons: To let users choose one item from a set of up to 5 mutually exclusive, related options." "Combo boxes: To let users choose from a set of options in a compact dropdown." Hyperlinks to navigate. "Buttons: To let users initiate an immediate action." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- "When a user changes a setting, the app should immediately reflect the change — don't require a confirmation button." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- RadioButtons: "Use radio buttons when users need to see all options before they make a selection. Radio buttons emphasize all options equally". "Unless all options deserve equal attention... to recommend a single best option... use a combo box". "If there are more than eight options, use a combo box." "If the available options are based on an app's current context, or they can otherwise vary dynamically, use a list control." "Don't put two RadioButtons groups side by side." — [Radio buttons](https://learn.microsoft.com/en-us/windows/apps/design/controls/radio-button)
- ComboBox: "When there are fewer than five items, consider using radio buttons"; "Use a combo box when the selection items are of secondary importance in the flow of your app"; "Limit the text content of combo box items to a single line"; "Sort items... place the most common options at the top." By default SelectionChanged fires only on commit (click/Enter). Set `SelectionChangedTrigger=Always` for live update while arrowing through the open list. — [Combo box](https://learn.microsoft.com/en-us/windows/apps/design/controls/combo-box)
- Slider: "Use a slider when you want your users to be able to set defined, contiguous values (such as volume or brightness)". "A slider is a good choice when you know that users think of the value as a relative quantity, not a numeric value." "Is the setting an exact, known numeric value? If so, use a numeric text box." "Does the setting have a range of four or more values? If not, use radio buttons." — [Sliders](https://learn.microsoft.com/en-us/windows/apps/design/controls/slider)
- Slider recommendations: "Give immediate feedback while or after a user makes a selection (when practical)"; "Use labels to show the range of values"; "Disable all associated labels or feedback visuals when you disable the slider"; "Don't change the size of the slider thumb"; "Don't use a slider as a progress indicator." — [Sliders](https://learn.microsoft.com/en-us/windows/apps/design/controls/slider)
- Slider steps and value: "Use step points if you don't want the slider to allow arbitrary values... Give it a step value of 1"; "make sure that the final step aligns to the slider's max value"; "Show tick marks and a value label when users need to know the exact value... Otherwise, they can use the value tooltip"; "If you need a value label, display it below the slider. Center the text relative to the control and include the units"; "Since the slider's thumb is covered during scrubbing, consider showing the current value some other way". — [Sliders](https://learn.microsoft.com/en-us/windows/apps/design/controls/slider)
- Slider labels: "Use a label with no ending punctuation"; position labels above or beside the slider to match the form, and "Avoid placing labels below the slider"; range labels should be one word and parallel ("Low/High"); a volume slider "could display a speaker graphic without sound waves at the minimum end... and a speaker graphic with sound waves at the maximum end." — [Sliders](https://learn.microsoft.com/en-us/windows/apps/design/controls/slider)
- Buttons: "Don't use a Button control when the action is to navigate to another page; instead, use a HyperlinkButton". "Usually button text is a single word that is a verb." "minimum button width of 120px"; "maximum length of 26 characters". "Expose only one or two buttons to the user at a time". "In pages that contain a single button (for example, an Apply button at the bottom of a settings page), you should left-align the button." — [Buttons](https://learn.microsoft.com/en-us/windows/apps/design/controls/buttons)
- Accent colour: "Accent colors are used sparingly to highlight important elements and convey information about an interactive element's state." "Use color meaningfully." — [Color in Windows](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/color)
- In ContentDialog, the DefaultButton "receives the Accent Button visual treatment" and responds to Enter. — [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs)
- PowerToys uses `AccentButtonStyle` on its "check for updates" button and plain buttons everywhere else. — [PowerToys GeneralPage.xaml](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Views/GeneralPage.xaml)
- Segmented control: Microsoft ships it as `CommunityToolkit.WinUI.Controls.Segmented` (NuGet). I could not retrieve a Microsoft guidance page for it (the learn.microsoft.com URL I tried returned 404). — [NuGet: CommunityToolkit.WinUI.Controls.Segmented](https://nuget.org/packages/CommunityToolkit.WinUI.Controls.Segmented)

### Inferences
- Brightness/contrast: horizontal Slider 0–100, StepFrequency 1, applied live on drag (debounced or throttled to the DDC/CI write rate), with the numeric value shown beside the slider. The Windows Settings Display page does show a numeric value tooltip on its brightness slider (observation; no doc found). Optional sun icons at the ends follow the "speaker graphic" pattern.
- Input source: the options vary by monitor (detected or capability-driven), so a ComboBox fits ("options... vary dynamically"). It also keeps a long DP/HDMI/USB-C list compact. RadioButtons only if there are 2–5 fixed inputs and all deserve equal weight.
- Colour mode (preset list, often 5–10 entries): ComboBox. Segmented is acceptable for 2–4 short labels, but the Microsoft-documented equivalent is RadioButtons with MaxColumns for a horizontal row.
- "Run in background with tray icon", "Start with Windows": ToggleSwitch cards (immediate effect).
- No guidance says "exactly one accent button per view" as a hard rule. The documented basis is "accent... used sparingly" plus the dialog DefaultButton getting the accent treatment. Treat "at most one accent button per view, and never on destructive actions" as an inference consistent with these sources and with PowerToys practice.

### Gaps
- No Microsoft doc found that states a literal "one accent button per view" rule.
- No Microsoft usage guidance found for the Toolkit Segmented control (when to use vs RadioButtons).

## Status and messaging: InfoBar, TeachingTip, inline validation, empty states, "device not connected"

### Takeaway
Use an InfoBar for persistent, app-wide status changes such as "monitor not responding" or "DDC/CI disabled". Error severity with IsClosable=false is for blocking conditions that clear when resolved. Warning is for conditions that may cause problems later. Success is for completed background tasks. Use a ContentDialog only when the user must read or decide. Use a TeachingTip only for transient teaching, never for errors. Show validation inline, not in dialogs.

### Cited Findings
- InfoBar purpose: "Use an InfoBar control when a user should be informed of, acknowledge, or take action on a changed application state." "An InfoBar will take up space in your layout... It will not cover up other content or float on top of it." "Do not use an InfoBar control to confirm or respond directly to a user action that doesn't change the state of the app, for time-sensitive alerts, or for non-essential messages." — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- Examples of InfoBars that are closed by the user or when resolved ("directly impact app perception"): "Internet connectivity lost"; "No microphone plugged in when attempting to record"; an error while auto-saving. — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- Severity meanings: "Error: An error or problem that has occurred. Warning: A condition that might cause a problem in the future. Success: A long-running and/or background task has completed. Default: General information that requires the user's attention." "Icons and color should not be the only UI components signifying meaning". — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- Non-dismissible: "If the notification is required to be in view until the status is resolved... you can set the IsClosable property to false." Example: Severity Error, Title "No Internet", Message "Reconnect to continue working.", IsClosable False, ActionButton "Network Settings". — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- Flashing: "The InfoBar should not appear and disappear from view rapidly"; for status-driven InfoBars, "include logic in your application to prevent content from appearing or disappearing rapidly or multiple times in a row". To make screen readers announce updated content, "close and re-open the control". — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- InfoBar can host an indeterminate ProgressBar as custom content ("Backup in progress", IsClosable False). — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- When to use other controls: Flyout for information "in context of a specific UI element". "For scenarios where the application is confirming a user action, showing information the user ***must*** read, use a ContentDialog." Also use a ContentDialog "if a status change to the app is so severe that it needs to block all further ability for the user to interact with the app". "For scenarios where a notification is a transient teaching moment, a TeachingTip is a better option." — [InfoBar](https://learn.microsoft.com/en-us/windows/apps/design/controls/infobar)
- TeachingTip: "Because teaching tip is transient, it would not be the recommended control for prompting users about errors or important status changes." "Tips are impermanent and should not contain information or options that are critical". "users, on average, only read 3-5 words and only comprehend 2-3 words". — [Teaching tips](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/teaching-tip)
- Inline validation: "Don't use dialogs for errors that are contextual to a specific place on the page, such as validation errors... use the app's canvas itself to show inline errors." — [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs)
- PowerToys uses informational InfoBars with a shield icon to explain policy-managed (GPO) settings, InfoBars with a restart action button after language changes, and InfoBars with dynamic severity for backup/restore results. — [PowerToys GeneralPage.xaml](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Views/GeneralPage.xaml)
- Notification-area overlays for status (legacy guide): standard overlays exist for Warning, Error, "Disabled/Disconnected", "Blocked/Offline", with "a single overlay... bottom-right". — [Notification Area (Win7 UX guide)](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)

### Inferences
- "No monitor found" (none detected) is an empty state. Replace the cards with a centred message, icon and a "Detect again" button rather than greying every control. "Monitor not responding / DDC/CI off" (a monitor is present but control fails) is a changed app state: show a non-closable Error or Warning InfoBar at the top of the page with an action button ("Retry"), and disable the dependent cards. This matches the "No Internet" / "No microphone" examples.
- Debounce connect/disconnect events before showing or hiding the InfoBar, per the no-flashing guidance.
- Brief success after a reset or input change can be a Success InfoBar, or nothing at all, since the visible state change is the feedback.

### Gaps
- I found no Microsoft design doc on empty states for Windows apps, and none describing how the Windows Settings app shows disconnected Bluetooth devices ("Paired"/"Not connected" status text under the device name is an observation, not documented guidance).

## Disabled vs hidden controls and explaining why

### Takeaway
Keep the same settings visible in every context, disable (not hide) the ones that don't currently apply, and use the card's Description, or an InfoBar for a whole group, to say why. The exception: in tray context menus, remove items that don't apply rather than disabling them.

### Cited Findings
- "Display the same settings regardless of the app context. If some settings aren't relevant in a certain context, disable the `SettingsCard` by setting `IsEnabled` to `false`." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- "Add a descriptive message if one of the controls is disabled. Use the `Description` property of `SettingsCard` to explain why the setting is unavailable." — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- PowerToys example string: "This setting can only be changed when running as administrator" (Description on "Always run as administrator"), plus GPO InfoBars ("some settings are managed"). — [PowerToys Resources.resw](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/Strings/en-us/Resources.resw); [PowerToys GeneralPage.xaml](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Views/GeneralPage.xaml)
- Slider: "Disable all associated labels or feedback visuals when you disable the slider." — [Sliders](https://learn.microsoft.com/en-us/windows/apps/design/controls/slider)
- Tray menus (legacy guide): "Remove rather than disable any context menu items that don't apply." Also "Don't disable notification area icons. If the icon doesn't currently apply, remove it." — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)

### Inferences
- A capability the connected monitor doesn't support (e.g. no colour-mode VCP) could either be disabled with a Description ("Not supported by this monitor") or hidden. The Microsoft settings guidance favours disable-and-explain for context-dependent settings.

### Gaps
- No current (Windows 11) general rule on disable vs hide beyond the settings-page guidance above.

## Progress: ProgressRing vs ProgressBar, determinate vs indeterminate, placement, delay thresholds

### Takeaway
Use an indeterminate ProgressBar for non-blocking "Loading/Retrieving" work, an indeterminate ProgressRing when the user must wait ("Connecting…"), and determinate when the duration is known. Show nothing for sub-second work. Treat 2 seconds or more as "lengthy". For work usually under about 5 seconds, prefer a lightweight activity indicator over a progress bar.

### Cited Findings
- "The *indeterminate* state for ProgressBar shows that an operation is underway, does not block user interaction... The *indeterminate* state for ProgressRing shows that an operation is underway, blocks user interaction with the app". — [Progress controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/progress-controls)
- Keywords: ProgressBar for "Loading...", "Retrieving", "Working..."; ProgressRing for "Refreshing", "Signing in...", "Connecting...". — [Progress controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/progress-controls)
- "Sometimes a task is obvious enough that it doesn't require a progress control at all – and sometimes... a line of text is still necessary". "Does the user only care about the completion of the operation? Sometimes it's best to show a notice only when the operation is completed". ProgressRing minimum 20x20 epx, so set Width and Height equal. — [Progress controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/progress-controls)
- Thresholds (legacy guide): "users are aware of response times of over one second... consider operations that take two seconds or longer to complete to be lengthy and in need of some type of progress feedback." "Will the operation complete in about five seconds or less? If so, use an activity indicator instead... If the operation usually takes five seconds or less but sometimes takes more, start with a busy pointer and convert to a progress bar after five seconds." — [Progress Bars (Win7 UX guide)](https://learn.microsoft.com/en-us/windows/win32/uxguide/progress-bars)
- Also from the legacy guide: "Don't combine a progress bar with a busy pointer"; "Don't put the percentage complete or any other text on a progress bar"; label "Start the label with a verb (for example, Copying) and end with an ellipsis"; Cancel if no side effects, else Stop. — [Progress Bars](https://learn.microsoft.com/en-us/windows/win32/uxguide/progress-bars)

### Inferences
- Monitor enumeration/DDC capability probing at startup (1–3 s) suits an indeterminate ProgressRing with "Detecting monitors…" or a thin indeterminate ProgressBar at the top of the content, shown only if the work exceeds about 1 s to avoid a flash. Individual VCP writes need no progress UI; the slider position is the feedback.

### Gaps
- No current WinUI doc gives a numeric delay before showing progress. The 1 s / 2 s / 5 s figures come only from the Windows 7-era guide.

## Destructive / guarded actions: ContentDialog (title, buttons, default button, wording) vs MessageBox; confirmation copy

### Takeaway
Use a ContentDialog (not the deprecated MessageDialog/MessageBox style) for factory reset and power off. The title should be a question, the body should state the consequence, and the primary button should carry a specific verb ("Reset", "Turn off"), with "Cancel" as the CloseButton. For risky actions the default (Enter) should be the safe choice, so don't make the destructive button the DefaultButton/accent.

### Cited Findings
- Dialog rules: "Clearly identify the issue or the user's objective in the first line"; title "is the main instruction and is optional... Make sure that the title relates directly to the button choices"; content "Don't repeat the title with slightly different wording"; "Ensure that your dialog has at least one button corresponding to a safe, nondestructive action like 'Got it!', 'Close', or 'Cancel'. Use the CloseButton API"; "Use specific responses to the main instruction... as button text"; "The 'do it' action button(s) should appear as the leftmost buttons. The safe, nondestructive action should appear as the rightmost button." — [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs)
- "Use the ContentDialog class to build your dialog experience. Don't use the deprecated MessageDialog API." — [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs)
- Canonical destructive example: Title "Delete file permanently?", Content "If you delete this file, you won't be able to recover it. Do you want to delete it?", PrimaryButtonText "Delete", CloseButtonText "Cancel". — [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs)
- CloseButton handles click, Esc, system back and Gamepad B, and returns `ContentDialogResult.None`. DefaultButton gets the accent visual, responds to Enter and receives initial focus. "By default, no default button is set." Only one ContentDialog can be open per window. — [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/design/controls/dialogs-and-flyouts/dialogs)
- Confirmation necessity (legacy guide): "confirmations are most effective when used to confirm actions that have significant or unintended consequences"; "Frequent confirmations are annoying". Alternatives include preventing errors by physically separating destructive commands, and providing undo. — [Confirmations (Win7 UX guide)](https://learn.microsoft.com/en-us/windows/win32/uxguide/mess-confirm)
- Defaults: "Risky action confirmations | Don't proceed (or the safe choice)." — [Confirmations](https://learn.microsoft.com/en-us/windows/win32/uxguide/mess-confirm)
- Wording: "Never use OK and Cancel for confirmations." "To close a program or restart Windows, use specific responses to the main instruction... don't use Close or Yes/No". "For risky action confirmations, use the term permanently to indicate that an action can't be undone." "Don't use 'warning' or 'caution' in the text." Use "anyway" in the commit label for unintended-consequence confirmations ("Uninstall anyway"). "Are you sure you want to [perform an action]?" connotes confirming the direct result of a user request. — [Confirmations](https://learn.microsoft.com/en-us/windows/win32/uxguide/mess-confirm)
- "Don't show this message again": "Use this option only for the routine and ulterior motive confirmation patterns." — [Confirmations](https://learn.microsoft.com/en-us/windows/win32/uxguide/mess-confirm)
- Button order when several buttons serve one decision: "OK/[Do it]/Yes; [Don't do it]/No; Cancel". — [Buttons](https://learn.microsoft.com/en-us/windows/apps/design/controls/buttons)

### Inferences
- Factory reset: Title "Reset monitor to factory settings?". Content: "This restores brightness, contrast, colour and other settings on <Monitor name> to their factory values. You can't undo this." Primary "Reset", Close "Cancel", DefaultButton = Close (or none).
- Power off: Title "Turn off <Monitor name>?". Content explains that the app may not be able to turn it back on over DDC/CI and that the user may need the monitor's power button. Primary "Turn off", Close "Cancel".
- Routine reversible changes (input switch, colour mode) should not get confirmations.

### Gaps
- There is no Windows 11 (WinUI) doc that restates the "default to the safe choice for risky actions" rule. It comes from the Windows 7-era confirmations guide. The WinUI doc only says "By default, no default button is set."

## Title bar: standard vs custom, Mica into title bar, icon/title placement, caption buttons, minimum sizes

### Takeaway
The standard Windows 11 title bar is 32 px high (48 px only when it holds interactive content such as search). It has a 16×16 icon 16 px from the left edge, the title 16 px after the icon in Caption style (Segoe UI Variable), and system caption buttons. Mica is the recommended backdrop for long-lived windows. Extending it into the title bar requires a custom title bar with transparent caption-button backgrounds. Inactive windows must visibly dim the title bar text, icons and buttons.

### Cited Findings
- "The standard title bar has a height of 32px." "The title bar's default background is Mica, however we recommend that title bars blend with the rest of the window if possible." "All title bar elements should be semi-transparent when the window is inactive." — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)
- Icon: "The size of the window icon is 16px by 16px." "Place the icon 16px from the left-most border". "When the title bar height is 32px, the top and bottom margins are 8px." Single-click on the icon shows the system menu; double-click closes. — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)
- Title: "Place the window title 16px from the window icon or back button"; "should use the Segoe UI Variable (if available) or Segoe UI font"; "should use *caption* style text"; may truncate with ellipsis, but "The icon and caption buttons... should always be fully visible." — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)
- Behaviour: empty or non-interactive title bar space must be draggable. Right-click shows the system menu. Double-click toggles maximise/restore. Colours adjust for high contrast (use `SystemColors`) and light/dark. — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)
- Custom caption buttons (if drawn): glyphs E921 ChromeMinimize, E922 ChromeMaximize, E923 ChromeRestore, E8BB ChromeClose; "full bleed backplates"; states rest/hover/pressed/active/inactive. — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)
- "Increase the size of the title bar to 48px when you include a searchbox" (same for a person picture). — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design)
- Implementation doc: full customisation is needed "to extend a material backdrop, like Mica, into the title bar area". Caption controls remain system-handled. "You should update the window title to show a meaningful display name for your app." The sample custom title bar is a 32 px Grid with a 16×16 icon at Margin 8,0,0,0 and title TextBlock CaptionTextBlockStyle at Margin 28,0,0,0. — [Title bar customization](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar)
- Do's: "Do make it obvious when your window is active or inactive. At a minimum, change the color of the text, icons, and buttons"; "Do define a drag region along the top edge". No interactive UI under the caption-button area, and AppWindow APIs (usable from WPF) use physical pixels, so scale them. — [Title bar customization](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar)
- Note: the design page and the code sample differ slightly. The design page says icon 16 px from the edge and title 16 px from the icon; the code sample uses an 8 px icon margin and a 28 px title offset. — [Title bar design](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design) vs [Title bar customization](https://learn.microsoft.com/en-us/windows/apps/develop/title-bar)
- Mica: "paint the background of long-lived windows such as apps and settings"; "apply Mica or Mica Alt as the base layer of your app, and prioritize visibility in the title bar area". The content layer uses `LayerFillColorDefaultBrush` (standard or card pattern). Mica falls back to a solid colour (`SolidBackgroundFillColorBase`) when transparency is off, in Battery Saver, on low-end hardware, when the window is inactive, or below build 22000. "Don't apply backdrop material more than once in an application." — [Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)

### Inferences
- For a small WPF utility, the system title bar plus DWM Mica (or a custom 32 px title bar with transparent caption buttons) satisfies the guidance. A custom bar is only needed if Mica must flow into the title area.
- Minimum window width: the NavigationView breakpoints (640/1008 px) and SettingsCard wrap thresholds suggest a minimum width around 500–640 px so cards don't wrap awkwardly. This is an inference; no doc prescribes a minimum.

### Gaps
- No Microsoft doc found that prescribes a minimum window size for Windows 11 apps.

## Notification area (system tray): icon design, click behaviour, context menu, minimise-to-tray, startup

### Takeaway
The only detailed Microsoft tray guidance is the Windows 7-era UX guide, which still applies "in principle". Left-click shows what users most want (a small flyout or the main window). Right-click shows the context menu: "Open" first in bold, toggles with check marks, then "Exit" last. Use a simple, recognisable 16/20/24 px icon, with status overlays at bottom-right. Use a tooltip (infotip) naming the app/device and status. Minimise-to-tray must be opt-in. Startup and tray visibility should be user-controllable toggles, as PowerToys does.

### Cited Findings
- Icon sizes: "Use an icon with 16x16, 20x20, and 24x24 pixel versions." "Prefer icons with unique outlines... prefer symbols over realistic images." "Avoid swaths of pure red, yellow, and green in your base icons." "Don't flash the icon." "Don't use long-running animations". — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Status overlays: Warning, Error, Disabled/Disconnected, Blocked/Offline; "Use only a single overlay, and locate it bottom-right". — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Hover: "Display a tooltip or infotip that indicates what the icon represents." Format "(Company name) Feature, program, or device name - Status summary"; "Don't explain how to interact with the icon"; no version numbers. — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Left single-click: "Display whatever users most likely want to see", e.g. "A flyout window, dialog box, or program window with the most useful settings"; "Users expect left single-clicks to display something". "Prefer using a popup window over a dialog box... Show only the most common settings and have them take immediate effect... Dismiss the popup window if the user clicks anywhere outside". "Display small windows near the associated icon." Click events occur "on mouse up, not mouse down". — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Double-click: "Perform the default command on the context menu". Right-click: "Display the context menu, with the default command in bold." — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Context menu order: Open (default, first, bold), Run; separator; Suspend/resume or enable/disable (check mark), "Minimized to notification area" (check mark), opt in to notifications, "Display icon in notification area"; separator; "Options"; "Exit". "Use check marks to indicate state." "be specific about what is being opened". "Don't have an About command" unless the program has no desktop presence. "The Exit command quits the program for the current Windows session and removes the icon." — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Minimise to tray: "consider providing the ability to minimize programs to the notification area only if all of the following apply: The program can have only a single instance. The program is run for an extended period of time. The icon shows status. The icon can be a notification source. Doing so is optional and users must opt in." "Use the Minimize button on the application's title bar, not the Close button." The guide also notes this pattern "is no longer recommended for Windows 7. Use regular taskbar buttons instead". — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Defaults: "Don't turn everything on by default and expect users to turn features off." — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- Terminology: "Refer to the notification area as the notification area, not the system tray." — [Notification Area](https://learn.microsoft.com/en-us/windows/win32/uxguide/winenv-notification)
- PowerToys (current): "Run at startup" ("PowerToys will start automatically when you log in to Windows"); "Show system tray icon" ("You can use this icon to open the PowerToys settings app or the PowerToys flyout"); "Show theme-adaptive system tray icon" (monochrome icon that adapts to light/dark); a Quick Access flyout with its own shortcut. — [PowerToys General settings](https://learn.microsoft.com/en-us/windows/powertoys/general)
- PowerToys string: "Run at startup" / "PowerToys will launch automatically". — [PowerToys Resources.resw](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/Strings/en-us/Resources.resw)

### Inferences
- For this app: left-click opens or restores the main window (or a small brightness flyout near the tray). Right-click menu: **Open <App>** (bold), separator, quick toggles or presets if any, separator, "Settings", "Exit". A theme-adaptive monochrome icon matches Windows 11 and PowerToys. Add a disconnected overlay or variant when no monitor is controllable.
- Closing the window while "Run in background" is on can hide to tray. This deviates from the Win7 note ("Minimize... not the Close button") but is common practice (PowerToys keeps running when its settings window closes). It must be opt-in and explained in the toggle's description.

### Gaps
- No Windows 11-era Microsoft doc on notification-area icon behaviour was found; the only detailed guidance is the 2020-dated Windows 7 guide. The Windows 11 tray-overflow behaviour ("hidden icons" menu) is not documented as design guidance.

## Keyboard shortcut editor (PowerToys pattern)

### Takeaway
PowerToys shows each hotkey as a row of keycaps with an edit button inside a SettingsCard. Clicking opens a ContentDialog that captures keys live, renders them as large keycaps, and validates as the user types. Save is the default accent button and stays disabled until the combination is valid (modifier + key). Errors and conflicts show as InfoBars inside the dialog. Reset and Clear are secondary buttons.

### Cited Findings
- ShortcutControl: the button shows current keys as keycaps (`PreviewKeysControl`) with an edit icon. The dialog has Title `Activation_Shortcut_Title`, Primary `Activation_Shortcut_Save`, Close `Activation_Shortcut_Cancel`, and DefaultButton Primary. — [PowerToys ShortcutControl.xaml.cs](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Controls/ShortcutControl/ShortcutControl.xaml.cs)
- Save (IsPrimaryButtonEnabled) is disabled when the shortcut has zero keys, only one key, or fails validity checks. Esc clears the keys. Tab/Shift+Tab are filtered so focus can move. Ctrl+Alt without Win raises an AltGr warning. Conflicts are checked asynchronously against system and in-app hotkeys. Reset and Clear set the shortcut to empty. The edit button is disabled when the feature is disabled. — [PowerToys ShortcutControl.xaml.cs](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Controls/ShortcutControl/ShortcutControl.xaml.cs)
- Dialog content: instruction text (`InvalidShortcutWarningLabel`); keys rendered as `KeyVisual` (Padding 20,16, FontSize 16, accent style, error state); InfoBars for Invalid shortcut (Error), AltGr (Warning), detected conflict (Warning, shows conflict message) and potential conflict (Warning, with "Learn more" button); Reset (`Shortcut_ResetBtn`) and Clear (`Shortcut_ClearBtn`, visible only when keys exist) with tooltips. — [PowerToys ShortcutDialogContentControl.xaml](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Controls/ShortcutControl/ShortcutDialogContentControl.xaml)
- User-facing rule (PowerToys docs, via search snippet): a custom activation shortcut "will have to begin with the Windows key, Ctrl, Alt, or Shift." — [PowerToys Shortcut Guide docs](https://learn.microsoft.com/en-us/windows/powertoys/shortcut-guide)
- PowerToys has app-wide shortcut conflict detection: a "PowerToys shortcut conflicts" window where users can reassign, ignore specific conflicts, or remove shortcuts. — [PowerToys General settings](https://learn.microsoft.com/en-us/windows/powertoys/general)

### Inferences
- For WPF: a SettingsCard per hotkey ("Increase brightness", "Decrease brightness", "Switch input…"). The right side shows keycap Borders plus an edit (pencil) icon button. Clicking opens a modal dialog with capture, live keycaps, an inline InfoBar for "Invalid shortcut" or "Already used by …", Save (accent, disabled until valid), Cancel, and Reset to default / Clear.
- Registration failures (RegisterHotKey returns false because another app owns the combination) map to the PowerToys "conflict" Warning InfoBar.

### Gaps
- The exact English strings for the PowerToys shortcut dialog (title, instruction text, error messages) were not retrievable. The fetched Resources.resw excerpt did not include those keys (they may live in a different resource file).

## Microsoft reference apps to imitate

### Takeaway
WinUI 3 Gallery's Settings page and the Community Toolkit SettingsPageExample are the canonical, source-available templates for card layout and spacing. PowerToys Settings is the closest functional analogue: a utility with a tray icon, run at startup, hotkey editors, InfoBars for managed or disabled settings, and accent styling kept to the main action.

### Cited Findings
- Microsoft's settings guidance points to "the WinUI Gallery settings page and the Windows Community Toolkit SettingsControls sample" as complete implementation examples. — [Guidelines for app settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)
- WinUI 3 Gallery is on the Microsoft Store and GitHub, and every control doc links to it for interactive examples. — [Toggle switches](https://learn.microsoft.com/en-us/windows/apps/design/controls/toggles)
- PowerToys General page structure (groups, toggles, InfoBars, accent button usage). — [PowerToys GeneralPage.xaml](https://raw.githubusercontent.com/microsoft/PowerToys/main/src/settings-ui/Settings.UI/SettingsXAML/Views/GeneralPage.xaml); [PowerToys General settings](https://learn.microsoft.com/en-us/windows/powertoys/general)

### Inferences
- For WPF, the WPF UI library (lepoco/wpfui) or the .NET 9+ WPF Fluent theme are the practical routes to these visuals. That is outside this note's scope and should be checked by the researcher covering WPF theming.

### Gaps
- The Windows Settings app (Display page, brightness slider, Bluetooth device states) is closed source, and I found no Microsoft design doc describing its specific layouts. Any statements about it are observational.
