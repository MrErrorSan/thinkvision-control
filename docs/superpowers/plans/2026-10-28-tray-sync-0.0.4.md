# One view, live sync, lean tray (0.0.4)

Source: field test 2026-10-27 (screenshot: flyout floating mid-screen, clipped; input shown stale after another PC switched it). Memory investigation: [docs/research/tray-memory/2026-10-28-tray-memory.md](../../research/tray-memory/2026-10-28-tray-memory.md).

## Goal

- One view. The tray flyout is gone on every OS. Left-click on the tray icon (or the macOS menu-bar item's "Open") opens the main window, or brings it to the front.
- Right-click menu unchanged: Open, Day, Night, Switch to this PC, Exit (Linux keeps its brightness items).
- While the window is visible, it matches the monitor. It re-reads on show and on activation, then every 3 s. No polling while hidden or in the tray.
- Windows: after the window closes in background mode, tray memory returns to about 15 MB (from 55–65 MB).
- Version 0.0.4 released like 0.0.3.

## Key design decisions

- **Poll = the existing show-refresh.** `OnShowing()` already re-reads `DisplayCodes` (brightness, contrast, colour mode, RGB gains, input) through `ControlService.RefreshAsync`. Polling calls the same path. Reads share the DDC queue with writes, so a read never interleaves a write. `ControlService` already ignores readings for a code being dragged, and `RangeItem.Busy` ignores them while settling. No new guard is needed beyond "skip a tick while the previous refresh is still running".
- **The timer lives with the window**, not the view model. Start on show; stop on close, hide or minimize. WPF uses `DispatcherTimer`; Avalonia uses `DispatcherTimer`. Interval 3 s (my call).
- **An externally changed input shows quietly**, with no OSD (my call, user didn't object).
- **Restart-on-close (WPF only).** When the panel closes and `BackgroundMode` is on, call `Shutdown()` with a `_relaunch` flag. Then, at the very end of `OnExit` (after the pipe, hotkeys, tray and mutex are disposed), `Process.Start(Environment.ProcessPath, "--startup")`. Ordering matters: hotkeys must be unregistered and the mutex released before the new copy starts, or its `RegisterHotKey` fails and `HandOffOrTakeOver` forwards to the dying copy. Tray Exit and non-background close never relaunch.
  - Accepted cost: the tray icon blinks, and hotkeys are dead for about 1 s after closing.
  - Avalonia does not get it this round (not measured there; Linux/macOS untested on hardware).
- **Start-menu relaunch**: already fixed in 0.0.3 (`HandOffOrTakeOver`). The field report came from a pre-0.0.3 build. Re-verify only.

## Verification

- `dotnet build ThinkVisionControl.slnx -c Release` with no new warnings; `dotnet test`.
- WPF on this machine with background mode on (settings backed up and restored):
  - tray left-click opens the window; a second click while it's open brings it to the front; right-click shows the short list;
  - a second launch (as from the Start menu) while in the tray opens the window;
  - close → process restarts → Task Manager memory about 15 MB; hotkeys work again after about 1 s; tray Exit does not relaunch;
  - with the window open, change brightness on the monitor's OSD → the slider follows within about 3 s.
- Avalonia: `dotnet build -r linux-x64` passes; Linux tarball publishes.

## Review follow-ups (applied)

An independent review found two defects and three edge cases; all fixed before release:

- Polling stalled slider drags (reads wait 400 ms after each write). Activation and the timer now go through `ControlService.PollAsync`, which reads nothing during a drag or within 1 s of a write. Show keeps the full `RefreshAsync`.
- A failed poll escalated to "Not responding" plus a bounded reconnect burst, which could leave hotkeys dead after monitor standby. `PollAsync` stops quietly on the first failed read.
- Restart-on-close could cut off writes still under way. `OnPanelClosed` now waits 400 ms (slider debounce), then `ControlService.WhenQuietAsync(1 s, max 10 s)`, and cancels the restart if the window was reopened meanwhile.
- A forwarded `--startup` opened the window. Both apps now keep the tray only.
- `OnExit` disposals are wrapped so the relaunch always runs. The WPF flyout-only `confirm` parameter is gone.

Tests: 5 new `ControlServiceTests` (poll sees external change, no reads during drag or right after a write, failed poll stays connected, `WhenQuietAsync` timing). 95/95 pass.
