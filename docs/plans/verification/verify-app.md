## New issues (missed by the audit)

1. **Headless CLI runs (and `--get`) apply the Automatic Day/Night preset to the monitor. Severity: high when the feature is on.** `on_status` calls `self.auto_tick()` on every Connected (controller.rs:629-630) with no `headless` check. In a headless run `auto_phase` is always `None` (:221), so with Automatic Day/Night on, every one-shot command sends `ApplyPreset{origin: Schedule}` (:1292). It is sent *after* the queued CLI command (:621-624 run first), so `--step brightness=+5` is immediately overwritten by the preset's brightness. `--get`, meant to be read-only, can also write brightness/contrast/colour mode: `print_get` → `quit_if_headless` only requests quit, `auto_tick` still sends, and the engine thread runs it before main's `shutdown` (main.rs:98) sets `stop`. Fix: `if !self.headless.get() { self.auto_tick(); }` (and gate `arm_auto` the same way).
2. **Ctrl+1/2/3 don't work until something has keyboard focus, and stop working after a tab switch. Severity: medium.** The shortcut lives in an outer `FocusScope.key-pressed` (main.slint:35-41). Slint delivers keys only to the focus item and its ancestors (slint: i-slint-core/window.rs ~1303-1347), and the window sets no initial focus (no `forward-focus`; the compiler's focus_handling pass only follows `forward-focus`). Clicking tabs and tiles (TouchArea only) never focuses anything. Also, when focus is inside a page, switching tabs destroys that page (`if root.tab == N`, main.slint:124-127) and with it the focus item, so the next Ctrl+N goes nowhere. Fix: `forward-focus: <the FocusScope>` on `MainWindow`, and refocus it after a tab change; or use a capturing `capture-key-pressed` handler.
3. **Headless verbs other than `--get` print nothing when the monitor is unreachable. Severity: low-medium.** On a non-Connected status the queued verb goes through `run_cli` → `osd_not_connected` (controller.rs:417-421), which only shows the OSD. `print_result` is never called, so a script gets exit 1/5 with an empty stdout (and no JSON with `--json`). The same goes for the 5 s timeout (A1). Fix: call `print_result(unreachable_text, {"ok":false,...})` in that branch when headless.
4. **The `--get` timeout prints nothing either. Severity: low.** When connect takes more than 5 s, `quit_if_headless` sets exit 8 but `print_get` never ran, so `--json` users get no object. Fix: print the error object in `quit_if_headless` when `pending_cli` is not empty.
5. **Forwarded CLI verbs always exit 0 in the launching process. Severity: low.** `instance::start` returns `Forwarded` and main returns `Ok(())` (main.rs:49). The resident shows the OSD but the caller's exit code and stdout say nothing, which contradicts the documented exit codes. This also covers the 5 s "never answered" case (instance.rs:53). At least document it, or forward with a reply channel.
6. **The Windows single-instance mutex is session-scoped while the pipe is per user+session. Severity: low.** instance.rs:107 (unprefixed name = `Local\`, per session) vs :142. A second user launched with `runas` in the same session sees `Busy`, can't open the other user's pipe (current-user DACL, :170-205), waits 5 s and exits as "Forwarded" without doing anything. Fix: include the user SID in the mutex name (the installer check would need to change too).
7. **The Unix socket briefly has umask permissions. Severity: low.** Between `bind` (instance.rs:349) and `set_permissions(0o600)` (:357), another local user can connect and inject args on the shared `/tmp` fallback (A17). Fix: bind inside a 0700 directory.
8. **`select_input` relies on possibly stale `values`. Severity: low.** controller.rs:893 returns early when `st.value(INPUT) == Some(code)`. Values are never cleared (A4), so after the monitor is switched away by its own buttons and reconnects without a fresh 0x60 read, choosing the "current" tile does nothing. Fix: let the engine's pre-read (engine.rs:785-790) decide, and drop the UI-side early return.
9. **Every engine `Value` bumps that code's revision (controller.rs:579), so an open colour-mode `SyncCombo` and Monitor combos are pushed back to `index` on each poll-driven change.** Combined with A3, any background value change (e.g. brightness changed with the monitor's buttons, seen by the 3 s poll) rebuilds the whole Monitor tab while the user is on it. Severity: folded into A3 (high). The fix is A3's.
