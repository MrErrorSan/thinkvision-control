# Localisation (Wave 6)

**Tier 2.** It touches every UI file and adds a cross-crate contract: the catalog API and the language setting.
**When:** it starts after the Linux in-app setup and the tray revert land. Both edit the same UI and controller files.

## Languages
- English (`en`, the source)
- Spanish (`es`)
- Simplified Chinese (`zh_CN`)
- French (`fr`)
- German (`de`)

**Assumption:** "the 5 most common" is read as the languages most used for desktop software. By number of speakers, Hindi and Arabic would rank higher. Arabic needs right-to-left layout and Hindi needs Devanagari font coverage, so both are better as a follow-up wave. Portuguese and Japanese are the next candidates.

## Key design decisions
1. **Two catalogs, one format.** Slint strings use `@tr()` with Slint's bundled translations (`slint_build::CompilerConfiguration::with_bundled_translations`; `translations/<lang>/LC_MESSAGES/tvc-app.po`; switched with `slint::select_bundled_translation`). Rust strings use `tvc_core::i18n`, which parses `translations/<lang>/LC_MESSAGES/tvc.po` embedded with `include_str!`. Both are gettext `.po`, so translators see one format and one folder. The alternative, routing Rust strings through Slint, would need its unstable `private_unstable_api::translate`.
2. **The language follows the OS**, unless Settings → Language picks one: "System", English, Español, 简体中文, Français, Deutsch. Each name is shown in its own language. Changing it applies at once: Slint re-evaluates every `@tr` binding, and the controller re-renders the Rust strings.
3. **Not translated:** the command line (`--help`, messages and JSON stay English, because scripts and support threads rely on them), log.txt, register IDs and MCCS code names in the capability report. Everything shown in the window, the OSD, the tray tooltip, the setup cards and dialogs is translated.
4. **Monitor-provided text is never translated:** model names, `vcpname` names and input labels the monitor reports. Profile labels written by us (p32p20.json "Brightness", colour-mode names) are translated through the Rust catalog by their English text.
5. **Placeholders are positional** (`{0}`, `{1}`) in both catalogs, so word order can change per language. `trf("Restored {0} of {1} settings.", &[n, m])`. Plurals use `msgid_plural` with fixed rules: `en`/`es`/`de` use n != 1, `fr` uses n > 1, and `zh_CN` has a single form.
6. **Fonts:** the UI text font stays the system one. Chinese needs a CJK system font: on Windows, Microsoft YaHei ships by default; on Linux the checklist adds noto-cjk. The icon font is unaffected.
7. **Layout:** German and French run about 30 % longer. Cards already wrap at 360 px from Wave 4, and the pseudo-locale pass (every string padded by 40 %) catches clipping before real translations land.

## Pinned contract (w6-infra)
```rust
// tvc_core::i18n
pub const LANGUAGES: &[(&str /*code*/, &str /*native name*/)] = &[("en","English"),("es","Español"),("zh_CN","简体中文"),("fr","Français"),("de","Deutsch")];
pub fn set_language(code: &str);            // unknown codes fall back to "en"
pub fn language() -> &'static str;
pub fn tr(msgid: &'static str) -> String;   // the English text when untranslated
pub fn trf(msgid: &'static str, args: &[&dyn std::fmt::Display]) -> String;   // {0}, {1}…
pub fn trn(msgid: &'static str, plural: &'static str, n: u64, args: &[&dyn std::fmt::Display]) -> String;
pub fn best_match(os_locales: &[String]) -> &'static str;   // "de-AT" → "de", "zh-Hans-CN"/"zh_CN" → "zh_CN", else "en"
```
- **Settings:** `"Language": "System" | "<code>"`, default "System".
- **Locale per OS:** `platform::locale::preferred() -> Vec<String>`. Windows uses `GetUserPreferredUILanguages`; Linux uses `LANGUAGE`, `LC_ALL`, `LC_MESSAGES` and `LANG`; macOS uses `CFLocaleCopyPreferredLanguages`.

## Verification
- **Catalog test:** every `.po` parses; every msgid in the templates is present (an empty translation counts as missing); `{n}` placeholders match the source; no msgid is translated twice.
- **`best_match` tests** for regional and script variants.
- **The language switch at runtime:** Slint strings and Rust strings both change, with no restart.
- **Screenshots in each language** at the default width and at 360 px, plus the pseudo-locale pass.
- **Translations are machine-drafted.** Each language is marked for review by a native speaker before 0.1.0 is announced in that language.

## Implementation notes
- Language codes are the catalog folder names: `es`, `zh_CN`, `fr`, `de` (gettext convention). Slint matches the folder name exactly, and picks the OS locale on its own at start-up.
- w6-infra core part landed: `tvc_core::i18n` (parser, `tr`/`trf`/`trn`, `best_match`, `LANGUAGES`), the `translations/` folders with empty `tvc.po` catalogs, and `Settings.language` (`"Language"`, None = System).
- **Command-line text stays English through `i18n::english(...)`.** The engine runs `Origin::Cli` commands inside it. The OSD shown for a command-line command therefore also uses English, which is accepted for 0.1.0.
- **Every string is wrapped.** That's 140 `@tr()` strings in the .slint files (135 template entries) and 332 Rust msgids. Profile labels, preset names and shortcut labels are translated where they're shown. The templates come from `scripts/extract-slint-strings.py` (it mirrors slint-tr-extractor, which doesn't build here) and `scripts/extract-rust-strings.py`.
- **Translations:** es, zh_CN, fr and de, complete for both catalogs. They are machine-drafted, and each needs a native speaker's review. The translators' notes on uncertain strings are in the session record: Lenovo menu feature names, Linux desktop menu paths, and gender agreement in es and fr.
- **The coverage test** (`i18n_tests::every_catalog_covers_its_template_with_matching_placeholders`) fails CI on any missing or empty translation, or on a placeholder mismatch. After changing UI text, re-run both extraction scripts and translate the new entries.
