## A. Real bugs and risks

### State / logic
- **A1. A headless CLI run can exit 0 with no output when the write is slow.** `start_headless` arms a 5 s safety quit at launch (controller.rs:293). `quit_if_headless` sets exit 8 only while `pending_cli` is non-empty (controller.rs:296-303). Once the command has been sent, the queue is empty. If its `Result` comes after 5 s, the process quits with the default exit code 0 and prints nothing. That happens with connect, a live capability read (~2.3 s, tvc-core/engine.rs:210), and an input switch with retries (attempts 5, settle 400 ms, p32p20.json:13). Fix: track an "in flight" flag and set exit code 8 when the timer fires.
- **A2. `--get` runs a second engine beside the resident one and shares its crash marker.** `--get` skips the single-instance check (main.rs:43-52). It then calls `Marker::left_over()` and `marker.clear()` (main.rs:62-64, 102). If the resident app is in the middle of a risky operation, the `--get` run (a) starts in safe mode for no reason and (b) deletes the resident's marker, so a real crash then goes undetected. Two processes also talk on the same DDC/CI bus at once, which risks collisions. The log file is shared too.
- **A3. The model sync rebuilds the Monitor tab on every render.** `sync()` compares rows with `PartialEq` (view.rs:62-74). `ControlGroup.rows`, `ControlRow.options` and `HotkeyRow.keys` are `ModelRc` fields. Slint's `ModelRc` equality is pointer identity (ASSUMPTION, from Slint's implementation). So every group and hotkey row counts as changed on each `render()` (view.rs:425, 459). Each changed `Value`, status change or toast-free save rebuilds every Monitor card: open combo popups close and keyboard focus is lost. This contradicts the module doc (view.rs:1-3). The engine sends `Value` only when a value changes (tvc-core/engine.rs:959-965), so this fires on real changes, not on every 3 s poll. Fix: compare rows by content (labels and indices), or keep stable inner `VecModel`s and sync them in place.
- **A4. `values`, `notes`, `range_note`, `finder` and `controls` are never cleared on disconnect or reconnect.** None of `on_status`, controller.rs:604-642, reset them. The old values stay on screen (disabled) and **Save current** still saves them: the button has no `enabled` binding (pages.slint:530-534, controller.rs:975-991), so it stores stale values as a preset while disconnected. With more than one monitor, this becomes cross-device bleed.
- **A5. Linux: setup hints block the UI thread.** `refresh_setup_hints` runs on every status change while the window is open, and on every show (controller.rs:637-639, 771-775, 797). On Linux, `hints()` scans `/proc` and runs `gdbus call --timeout=1` (setup.rs:20-27, 233-247). Its own doc says "call it off the UI thread or rarely" (setup.rs:14-16). The result is up to a 1 s freeze per status flip on GNOME.
- **A6. macOS: Login Items opens on every settings save.** `apply_settings` → `autostart::apply` runs on every save (controller.rs:431-448, 994-1003). While approval is pending, each call opens System Settings → Login Items (autostart.rs:157-160). Toggling any setting reopens it.
- **A7. Rapid retries leave several 16 s timers running.** Each "Try again" press starts a new 16 s timer that is never cancelled (controller.rs:1442-1447). An earlier timer can clear `retrying` while a later retry is still running.
- **A8. A confirm that arrives while a dialog is open is dropped silently.** `ask()` returns early if a dialog is already open ("counts as Cancel", controller.rs:862-864), but nothing is snapped back and the user gets no feedback. The same happens when no window is visible (controller.rs:860).
- **A9. Hotkey input switch falls back silently.** Input hotkeys look up `profile.inputs` by kind `"hdmi"/"dp"/"usbc"` (controller.rs:528, 538-547). The lookup is not limited to what the monitor advertises, and a miss does `return` with no OSD message.
- **A10. Monitor-tab order is parsed from the embedded P32p-20 JSON text at runtime.** `profile_rank` searches for `"code": "0xNN"` in the raw file (view.rs:305-311). It breaks if the JSON formatting changes, and it never reflects a user overlay or another profile.
- **A11. Confirm-skip rule.** `select_input` skips the confirm when the target is `this_machine_input` (controller.rs:900-904). CLI, tray and hotkey input switches never confirm (controller.rs:398-401, 461-467, 538-551). This conflicts with requirement (2), "input switches always confirmed", for experimental monitors.
- **A12. Custom colour is gated on the profile's custom mode.** `custom_colour_available = mode == profile.custom_colour_mode` (view.rs:408-409). With no 0x14 definition (an unknown monitor), the gains are disabled even when the monitor supports them. The hint then reads "Available in  colour mode", with a double space and an empty label (view.rs:410-415).
- **A13. Automatic Day/Night form breaks a binding.** `AutoDayNightCard.choice` is bound to `App.auto-mode`, then assigned (pages.slint:418, 431). After the first pick it no longer follows Rust. When Sun mode falls back to Off (controller.rs:1305-1308), the combo shows "Off" while the location form stays open. This may be intended, but the state is inconsistent.
- **A14. Two copies of the default restore text.** One is in controller.rs:193, the other in app.slint:28. The OSD comment says 264x64, but the size is 320 (background.slint:38 vs osd.rs:15). Low risk.

### Threading / platform
- **A15. The OSD window is identified by its title string.** main.rs:119 matches `"ThinkVision OSD"`, set in two places (osd.rs:13 and background.slint:46). Renaming one silently breaks the no-activate attributes.
- **A16. The OSD is always placed on the primary monitor's work area** (osd.rs:132-157). With several monitors it should appear on the display being changed, or on the one under the cursor.
- **A17. Unix single-instance socket collides between users.** When `XDG_RUNTIME_DIR` is missing, the socket falls back to the shared `/tmp/CoreFxPipe_tvc-cmd` (instance.rs:294-299). The lock is per user but the socket is not: a second user's primary cannot bind and loops remove/bind every 500 ms forever (instance.rs:348-356). Separately, the listener blocks on a client that never closes (instance.rs:358-363, and Windows instance.rs:244-252).
- **A18. Possible undefined behaviour in `WM_DEVICECHANGE`.** The handler builds a `&DEV_BROADCAST_DEVICEINTERFACE_W` before checking `dbch_devicetype` (monitor_events.rs:347-352). A smaller struct behind `lparam` makes that reference technically UB. Read the header first and cast afterwards.
- **A19. Shortcut editor assumes a US keyboard layout.** It maps Shift+digit by US symbols `")!@#$%^&*("` (controller.rs:1399-1401). AZERTY, QWERTZ and other layouts record the wrong key or get "This key can't be used".
- **A20. The engine may not shut down at exit.** `into_engine` relies on `Rc::try_unwrap` (controller.rs:238-240). If any `Rc<Controller>` clone is still alive, the engine is not shut down and the marker is cleared anyway (main.rs:96-102). This holds today, but nothing enforces it.
- **A21. Demo mode drops CLI verbs.** With `--demo` plus a verb, `start_resident` runs and the verb is never executed (main.rs:85-91). This is a developer-only flag.
- **Panics: none reachable found.** `osd.rs:58` unwraps right after assigning. `controller.rs:552` `unreachable!` is guarded at :518. `keycaps(..).remove(0)` is always non-empty. The `build.rs` unwraps are build-time only.

## C. Single-monitor assumptions and what multi-monitor needs

### Controller `State` (controller.rs:84-111)
- Per-display fields today held once: `profile`, `controls`, `values`, `status`, `failure`, `shown_status`, `range_note`, `notes`, `revisions`, `restore_text`, `finder`, `retrying`.
  - Needs: `displays: BTreeMap<DisplayId, DisplayState>` holding all of these, plus `name`, `kind` (external/built-in), `experimental`, `read_only_codes`, and a stable id (EDID mfg+product+serial, else connector path).
- App-wide fields that stay: `settings`, `setup_hints`, `hotkeys_available`, `failed_hotkeys`, `asleep` (the session is locked for every display), `auto_note`.
- `safe_mode` is global today. The crash marker should name the display being probed, so only that one is held.
- `displays: Option<Vec<AttachedDisplay>>` becomes the source of the switcher list (connected, controllable or not).
- `Controller` fields: `debounce: HashMap<u8, Timer>` (controller.rs:154) must be keyed by `(DisplayId, u8)`. `caps_requested` (:171) and `auto_phase` (:169) must be per display. `poll` sends `DISPLAY_CODES` to one link (:805-813).
- New field: `selection: Selection { One(DisplayId), Together }`.
- `State::def/value/firmware/revision/input_label` (controller.rs:113-137) move to `DisplayState`.

### Engine contract (tvc-core, consumed here)
- `Command::{Set, Step, DragTo, EndDrag, ApplyPreset, Refresh, Poll, Finder*, RestoreBackup, ReadCapabilities, SaveOverlay}` carry no display target. `Event::{Status, Controls, Value, Result, Finder, Displays}` carry no source.
- Needs: `DisplayId` on each, or one engine per display with a tagging wrapper. `Origin` stays. `Result` needs the id so window notes, toasts and the OSD can name the display.

### Render path (view.rs)
- `render(app, st)` (view.rs:364-466) flattens one display into globals. Keep that shape but pass `(&AppState, &DisplayState | Together)`.
- `header_name`, `status_line`, `banner` are single. The header needs the selected display. The banner needs either the selected display's state or a summary ("2 of 3 displays connected").
- `profile_text` (view.rs:462) should become per display ("Detected: <model> · Firmware … · Experimental").
- `profile_rank` (view.rs:305-311) should become a per-profile order, plus an MCCS fallback for unknown monitors.

### Tray (background.slint:6-36, controller.rs:450-481, tray.rs)
- One `connected` bool, one tooltip name, one status badge. Menu items "Day/Night preset", "Switch to this PC" and "Brightness up/down" have no target.
- Needs: badge = worst status across displays. Tooltip lists displays ("2 displays" or the names). Menu: per-display submenu or a "Target: All / <name>" radio group. Hide "Switch to this PC" for built-in panels and for displays without 0x60. Slint `Menu` supports `for` models, so add a `[TrayDisplay]` model.

### Hotkeys (controller.rs:484-555, tvc-core/hotkey.rs)
- `Action` has no target. Steps go to the one link.
- Needs a setting "Shortcuts control: All displays / Display under the pointer / <name>", using `MonitorFromPoint` on Windows (ASSUMPTION: a new platform helper). Input hotkeys apply only to displays that advertise the input. The built-in panel takes brightness steps only. The OSD names the target.

### OSD (osd.rs, controller.rs:739-764)
- One `Level` with "Brightness" and no name. Placed on the primary monitor only (A16).
- Needs: a label with the display name ("Brightness · P32p-20"), or for Together a mean or "All displays". Place it on the affected display, or on the cursor's display for "All".

### Schedules / automatic Day/Night (controller.rs:1265-1358)
- One `auto_phase`. One `ApplyPreset` to the one link. Runs only while that link is `Connected` (:1280).
- Needs: per-display phase tracking, so a display that connects later catches up on its own. Choose which displays the schedule applies to (default all). A failure toast names the display.

### Settings (tvc-core/store.rs:27-43)
- `day`/`night` presets hold raw `brightness`, `contrast` and a model-specific `colour_mode` value. Colour mode values differ across models, so one global preset is wrong.
  - Needs per-display presets (keyed by display id), or brightness/contrast as percentages with colour mode per display.
- `this_machine_input` is one value. It must be per display, and absent for built-in panels.
- Hotkey targets and the selected display (by stable id) need persisting.
- `auto_day_night`: add a target set.

### CLI (controller.rs:322-422, tvc-core/cli.rs)
- No display selector. `--get` prints one object (controller.rs:330-355). Exit codes describe one monitor.
- Needs `--display <id|name|all>`. `--get` output becomes an array or keyed object. Exit codes need a rule for partial success, for example "worst of".

### Window pages
- **Display page:** input tiles, sliders, presets and colour all bind to one display.
- **Monitor page:** profile groups, backup and the finder are all per display. The finder needs a fixed target for the duration of a snapshot/compare.
- **Settings:** "This PC's input" (pages.slint:510-521) and the presets (:523-536) are single.

## D. UI structure and the display-switcher plan

### Today
- **Window:** `MainWindow` (main.slint:13-163). Header: glyph, `App.model-name`, status glyph and text. Tab strip: Display, Monitor, Settings (Ctrl+1/2/3). One `ScrollView` holding the `App.banner` InfoBar and the page. Overlays: toast, `ShortcutDialog`, `DialogOverlay`.
- **Display page** (pages.slint:8-97):
  - `InputSelector` (`App.inputs`, `active-input`).
  - "Brightness and contrast" `SliderRow`s (`main-ranges`) and `range-note`.
  - Presets `TileButton`s (`presets`).
  - Colour: `SyncCombo` (`colour-modes`, `colour-mode-index`, `colour-revision`) and `ExpanderCard` with RGB `SliderRow`s (`custom-colour`, `custom-colour-available`, `custom-colour-hint`).
- **Monitor page** (pages.slint:99-157): `monitor-groups` → `Card`s holding a `SyncCombo`, `LabelledSwitch` or `Button` by `ControlKind`; Backup card; Tools → `FinderPage` (pages.slint:286-414, `finder-*` properties).
- **Settings page** (pages.slint:464-601):
  - System setup hints with Copy.
  - Startup switches.
  - This PC's input combo.
  - Presets with Save current.
  - `AutoDayNightCard`.
  - Hotkey rows → `ShortcutDialog`.
  - About.
- **Contract:** one `App` global (app.slint:5-104), all `in` properties plus 30-odd callbacks. Structs are in types.slint.
- **Feeding:**
  - Rust pushes everything through `view::render` (view.rs:364-466) whenever state changes and the window exists (controller.rs:839-844).
  - Models are diffed row by row with `sync` (view.rs:62-74).
  - "Snap back" uses `revision` ints (types.slint:30, 46; controls.slint:93-95, 348-350, 511-513).
  - Callbacks are wired once per window in `wire()` (controller.rs:1423-1526) and routed through the `with()` thread-local (controller.rs:43-52).
  - The window is dropped on close and rebuilt on open (controller.rs:816-831).
  - Callbacks carry VCP `code` (int) and an option index; the target display is implicit.

### Recommended minimal-churn design
Keep every existing page property as "the current view". Add one selection layer above them. Pages stay as they are; `render()` picks what to flatten.

1. **New types (types.slint)**
```slint
export enum DisplayState { connected, connecting, not-found, not-responding, asleep, unsupported }
export enum DisplayKindUi { external, built-in }
export struct DisplayEntry {
    id: string,            // stable: EDID mfg+product+serial, else OS device path; never an index
    name: string,          // from DDC model() / EDID name / OS friendly name; never hard-coded
    detail: string,        // "Connected over HDMI · Firmware LB1.2"
    state: DisplayState,
    kind: DisplayKindUi,
    experimental: bool,    // shows the badge; input switches always confirm
    can-input: bool,       // 0x60 usable → Input section and tray item
    can-colour: bool,
    has-settings: bool,    // false for the brightness-only built-in panel → hide/disable the Monitor tab
}
```
2. **New App properties and callbacks (app.slint)**
```slint
in property <[DisplayEntry]> displays;
in property <string> selected-id;          // "" = Together
in property <bool> together-available;     // ≥ 2 controllable displays
in property <bool> together;               // derived; convenient for pages
in property <bool> experimental;           // selected display's badge
in property <string> experimental-note;    // "Experimental: some settings are read-only…"
in property <bool> monitor-tab-available;  // false in Together and for built-in panels
callback select-display(string);           // id, or "" for Together
```
   - Keep `model-name`, `status-*` and `banner` as the selected display's values (or the Together summary). No page changes are needed for these.
3. **Header switcher (main.slint:44-84):** when `displays.length > 1`, replace the title `Text` with a dropdown button (name plus chevron). Alternatively add a chip row under the header: "All displays" plus one chip per display, each with a status dot and a ⚗ badge if experimental. `ComboBox` is the cheapest option but cannot show a badge or status. ASSUMPTION: a custom popup (`PopupWindow`) is needed for the badge. Hide the switcher with one display, so the screenshots stay the same.
4. **Together mode:**
   - Display page: brightness and contrast only, as **0-100 %**. Rust scales to each display's `max` on write, and the slider reads the mean or the first display's value. Presets apply per display. Hide Input and Colour (`inputs` empty, a new `colour-available` false). Show a note: "Changes apply to N displays".
   - Monitor tab: hidden or disabled (`monitor-tab-available`), with "Choose a display to change its settings".
   - Results: on partial failure, a toast that names the failing display.
5. **Rust:**
   - `State` → `AppState { settings, displays: BTreeMap<DisplayId, DisplayState>, selection, … }`.
   - `view::render(app, &AppState)` resolves `selection` to a `&DisplayState` (or builds a synthetic Together view) and calls today's per-display mapping unchanged.
   - Existing callbacks keep `(code, …)` and resolve the target with `self.targets() -> Vec<DisplayId>`. For Together, fan out `Command`s. `debounce` and revisions are keyed by `(id, code)`.
   - `select-display` saves the selection by id and re-renders. Its sync must replace all page models, since rows come from another device; `revision` bumps force sliders and combos to resync.
6. **Experimental monitors:**
   - Read-only codes go out as `ControlRow.enabled=false` plus a description "Read-only on this display". The field exists (types.slint:45) but `view.rs:353` always sets `true`.
   - `select_input` must always `ask()` when `experimental`; drop the `this_machine_input` shortcut at controller.rs:900. The tray, hotkey and CLI switches must also confirm, through the window or an OSD prompt, or be refused for experimental displays.
7. **Built-in panel (brightness only):** `DisplayEntry.kind=built-in`, `has-settings=false`, `can-input=false`. `main-ranges` holds brightness only. Colour, Presets-contrast and the Monitor tab are hidden.

## E. UX issues visible in the current UI

### Copy
- "Monitor" vs "display" are mixed: header "Your display" (view.rs:131), but "Looking for your monitor…" (view.rs:217, 244, 249) and "Your monitor is asleep" (view.rs:238). The tabs "Display" and "Monitor" don't say what is on each page; Display = picture, Monitor = OSD settings.
- The finder says "It now appears in **Monitor settings**" (controller.rs:1199), but the tab is called "Monitor".
- The voice switches between "We ask before you switch…" (pages.slint:514) and impersonal elsewhere. Factory reset says "We save a backup first" (p32p20.json:64).
- "Available in  colour mode" with a double space when there is no 0x14 (view.rs:414).
- About says "Monitor profile: ThinkVision P32p-20" for any monitor (view.rs:462).
- "isn't supported yet" (view.rs:172-173) contradicts the coming experimental mode.
- "Connected over HDMI" (view.rs:212) is the monitor's selected input, not necessarily how this PC is connected. Consider "Input: HDMI".
- The Not-responding banner body is 3 sentences with driver advice (view.rs:271). That is long for an InfoBar.

### Empty states
- **Never connected, no cached capabilities:**
  - Display page shows the "Brightness and contrast" header over an empty `CardFrame` (pages.slint:21-41, because `main-ranges` is empty).
  - The Colour section shows an empty combo and an empty-label hint (pages.slint:62-96).
  - The Monitor page shows only Backup and Tools, with "Find hidden settings" enabled although nothing is connected (pages.slint:147-156).
  - Needs one clear empty card ("No display to control yet" plus Check again).
- **The Settings Presets list shows even with no display**, and Save current is always enabled (A4).
- **Input section disappears entirely** when the profile has no matching inputs (view.rs:111-119). For unknown monitors, show MCCS names (tvc-core/mccs.rs may have them, ASSUMPTION).

### Loading states
- No spinner or skeleton. Status "Looking for your monitor…" plus the banner, which is held back 1 s (controller.rs:644-654). The `—` value text for unknown values is good (controls.slint:128).
- The finder busy state shows "Reading the monitor…" but the buttons only disable; no progress indication.
- The live capability read (~2.3 s, after a 2 s delay, controller.rs:631-634) has no indicator. With a cold cache the first connect blocks on it with only "Looking for…".

### Error states
- Toasts (2.5 s, controller.rs:39) carry real failures for gains, input and colour mode (controller.rs:716-719). They are easy to miss, are not announced, and disappear while the user reads them.
- A disabled Monitor card gives no reason. The `enabled` field is always true (view.rs:353), so "disabled" only ever means disconnected.

### Accessibility
- **Not keyboard-reachable** (no FocusScope or `forward-focus`):
  - `Tab` (controls.slint:225-260): tabs only via Ctrl+1/2/3.
  - `TileButton` (controls.slint:142-200): input selector and preset tiles. **The input switch and the presets cannot be used from the keyboard.**
  - Finder back button (pages.slint:290-300), hotkey edit buttons (pages.slint:576-589), finder change rows (pages.slint:352-375).
  - They have `accessible-action-default`, so screen readers can use them, but sighted keyboard users cannot.
- `InputSelector` uses role `radio-group`, but its children are role `button` with `accessible-checked` (controls.slint:160-163, 211-212). They should be radio buttons. A disabled `TileButton` only lowers opacity and never exposes a disabled state (controls.slint:159).
- `DialogOverlay` and `ShortcutDialog` don't trap focus. Tab can move to controls behind the scrim, which only swallows clicks (controls.slint:443, pages.slint:162).
- Toast, banner and status changes are not live regions; screen-reader users don't hear write results or connection changes (main.slint:135-155, 117-123).
- Every `Card` is a `groupbox` labelled with its title, and the inner combo, switch or button repeats the same label (controls.slint:35-37; pages.slint:114, 120, 127), so screen readers announce it twice.
- `SectionHeader` is `accessible-role: none` (controls.slint:16), so screen readers get no headings for the sections.
- Contrast: disabled text `#ffffff5d` on `#2d2d2d` (theme.slint:17, 10) is low (expected for disabled). The selected `TileButton` text uses `Palette.accent-foreground`; with the salmon accent in display.png, check the contrast.
- `Segoe UI Variable Text` is hard-coded (main.slint:31, background.slint:52); other platforms fall back unpredictably.
- At `compact` width (< 520 px) the preset captions and "This PC" are hidden (pages.slint:56, controls.slint:217), so that information is gone, not wrapped.
